# AI 使用与贡献说明

本项目在开发和运行两个环节使用了 AI。开发期间，候选人给出业务约定、技术范围和验收标准，Codex 在共享工作区编写和修改代码、执行命令、检查结果并整理文档。运行期间，本地 Ollama 上的 `qwen2.5:7b-instruct-q4_K_M` 根据任务状态选择公开动作。下文分别记录三个角色实际承担的工作。

## 1. 候选人已明确参与的部分

- **定义业务语义。** 候选人选定“校园毕业季”作为最小示例，明确预算是活动预计执行费用，估算本身不扣费，耗时按串行相加。候选人还要求输入包含带时区的截止时间，相同任务重放不能重复保存，同一标识对应不同输入必须报冲突。
- **限定实现范围。** 候选人指定 Python CLI、四个本地业务工具和已有的本机 Qwen，要求显式区分真实模型与离线 Mock，把失败续跑列为加分项。
- **提出实验和停止条件。** 在模型反复估算的情况下，候选人要求保留失败 Trace，区分“摘要提到替代方案”和“实际选中替代方案”，预先固定用例和尝试次数。示例提示实验失败后，候选人明确要求停止该路线，只修复已有有效报价仍能重复估算的业务缺口。
- **提供交付目标。** 候选人提供了 GitHub 仓库地址，并授权整理和发布提交版本。

这些贡献可以从开发期间的任务说明确认。代码作者身份、候选人自行运行过的命令和人工投入时间，不能仅凭 Git 提交账号、文件时间或模型运行记录推定。

## 3. 运行时的模型、工具与程序分工

Qwen 选择评估哪个未报价候选、是否确认采用某个真实报价、发生异常后是否重新采取动作，以及何时停止。程序校验模型给出的结构化参数，执行工具并把实际观察交回下一轮。模型确认后，生成脚本、对脚本做绑定估算、校验并保存由程序按固定顺序组织。脚本正文来自本地模板，费用和耗时来自合成目录，普通步骤的自动执行不计作模型重新规划。

预算场景可以逐步核对这条边界。第 2 步工具算出视频费用 12，预算为 10。第 3 步 Qwen 的结构化动作选择图文，工具才返回费用 8。第 4 步模型确认采用该估算，后续程序生成脚本并保存。认定“改选”的依据是动作参数、对应工具返回和最终产物。日志只记录模型公开输出，不要求或保存内部思维过程。[预算 Trace](../examples/review/budget/trace.jsonl)

## 4. 验证结果如何归属

- **确定性验证。** 最终 59 项测试通过，覆盖费用计算、依赖、时间边界、重放、非法动作、保存和步数上限。离线 Mock 用预设规则选动作，可用于验证工程链路。它的预算改选不能计入 Qwen 的实测成绩。[测试结果](../examples/review/tests.txt)
- **真实模型验证。** 冻结示例提示的历史批次为 1 项通过、3 项失败。最终交付先执行正常、超预算改选、临时工具失败和全部超预算四个任务。发现最终缺口说明的数值缺陷后，仅复测受影响的一项。合计五次真实任务运行，包含原记录，不能视作五次独立成功。[历史批次](../examples/review/history-few-shot/)、[最终评估](03-evaluation.md)
- **候选人独立验证。** 上述运行由 Codex 在共享工作区执行。已有运行记录能说明程序和模型发生过什么，不能据此声称候选人已亲自复现。
