# 工程复盘

最难的问题是模型的公开摘要会说“评估图文”，实际 option_id 却仍指向视频。曾压缩上下文、拆分评估与确认、对调枚举顺序，并试过两段异业务示例。在示例版四例中，仅首选可行场景通过。一次单步诊断还表明：明确要求图文时模型能生成正确ID，因此没有证据支持把错误归因于解析器必然覆盖了参数。

最终修改着眼于业务约束：相同任务、方案、目录版本已有成功候选报价后，重复估算没有新信息。把实际有效报价转为可选确认动作，并用同一动作集合生成请求和执行前校验。可继续的候选越少，模型越不容易反复调用；即使只剩一个替代候选，模型仍必须实际选择，也可以停止。绑定脚本后的重新估算保留下来，用于检查制作依赖。

最后一个真实缺陷出在无可行输出。模型判断应停，但把最高报价的缺口当成最低缺口。程序现在分开存储原始摘要与费用表复核值。本批验证了这些具体行为，单次样本不足以说明换模型、换任务或长期运行的稳定性。

本版不做跨进程失败续跑、并发任务或真实投放。后续若扩展，优先验证不同目录、期限边界和多种可行替代。个人学习与实际贡献由候选人自行补充。
